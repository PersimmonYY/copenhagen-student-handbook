# 测试方法与限制

## 对照条件

- **A 组（普通 ChatGPT）**：新对话、原始问题、不提供 skill、手册、评分表或项目背景。
- **B 组（项目 skill）**：相同问题，明确使用对应 skill，可读取 skill 所指向的最小本地资料，并按要求实时核验。

本测试回答的问题是：“用户直接提问”和“在本项目 workflow、资料及约束下提问”相比，实际结果是否更可靠、更可执行。

## 不能完全控制的变量

ChatGPT 与 Codex 可能使用不同模型、系统指令、搜索工具和上下文，因此产品间 A/B 不是纯粹的 skill 因果实验。报告必须把以下贡献分开讨论：

1. 固定身份和风险边界带来的提升；
2. 本地手册与来源台账带来的提升；
3. 实时浏览能力带来的提升；
4. 模型或产品差异可能带来的提升。

如需更严格的因果测试，后续应在同一模型、同一工具权限、相同采样参数下运行两组，仅改变是否提供 skill。

## 记录字段

每次运行记录：日期、产品、显示的模型名称（如可见）、是否新对话、是否联网、实际引用来源、完整回答和异常。评分表不得在生成回答前提供给 A 组。

## 官方产品依据

OpenAI 官方说明将 skill 定义为可复用的指令、参考资料和可选脚本，并采用渐进加载；skill 可以显式或根据描述隐式触发。由此，本测试主要检验 workflow 一致性和领域约束，而不是期待 skill 提升底层模型本身的通用推理能力。
