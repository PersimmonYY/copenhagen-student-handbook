# 五个 skill 对照测试结果（2026-09-03）

## 结论

这五个 skill **有实质提升**，但结论应表述为“这套领域 workflow + 本地手册 + 实时核验提高了可靠性”，不能证明底层模型本身因安装 skill 而变强。

- A 组（普通 ChatGPT）：**109/144，75.7%**
- B 组（本项目 skill）：**142/144，98.6%**
- 差值：**+22.9 个百分点**
- 六题的风险维度均未退步；按预先固化的阈值，达到“有实质提升”。

## A 组的突出优点

普通 ChatGPT 并不差：T03 的立即停付和证据保全、T04 的 90 小时规则、T01 的主办理顺序都很实用，而且联网检索显著提高了回答质量。skill 的价值不是把一个错误百出的答案变正确，而是减少边缘条件遗漏和来源混用。

## skill 带来的关键行为

1. **固定目标读者**：即使题目没有重述身份，也保持中国籍、非欧盟、高等教育学生的默认语境。
2. **依赖式回答**：不只列事项，而是分清阻塞项、可并行项、必须等待和人工确认。
3. **结论强度控制**：对自雇、银行开户、MitID 等不把“通常路径”写成法律上的绝对条件。
4. **来源分层**：官方事实、服务方信息、编辑解释、个人经验和待确认内容分开。
5. **拒绝凑数**：职位检索宁可只返回 2 个，也不把发布日期、语言或有效性没有核实的结果混入主清单。
6. **版权和隐私边界**：社交平台内容先变成检索线索；经验匿名概括，引用或截图须有授权；内部审核不等于开源。

## 暴露的问题

### 普通 ChatGPT

- 来源常以站点名显示，缺少直接链接与核验日期，不便编辑组复查。
- 搜索结果数量多于证据质量：T05 对发布时间使用聚合站相对时间，并漏读 Nasdaq 的 Scandinavian language 硬门槛。
- 容易扩展到题目以外：T01 的中国境外收入提醒、T02 的 EU 路径增加了阅读成本。
- T06 虽有版权意识，但没有本项目的评论匿名化、免责声明和内部传播规则。

### 本项目 skill

- 职位发布时间的合格标准原先不够严格：应明确“无法核验原始发布日期时不得计入严格时间窗”。
- CPR 与 MitID 的关系需要更精确：对多数新生 CPR-first 是更顺的操作路径，但官方明确说 MitID 并不绝对要求 CPR。
- 实时职位检索受外部页面可访问性影响。本次 Agent Reach 的 LinkedIn 专用后端不可用，B 组使用公开页面和普通搜索回退；这不是 skill 自身能消除的问题。
- B 组由知道 rubric 的同一评审方生成并评分，存在期待效应；需要同模型盲测才能获得更强因果证据。

## 归因限制

本次提升由至少四部分共同产生：skill 的固定流程、手册本地知识、实时联网工具以及 ChatGPT/Codex 产品与模型差异。OpenAI 官方将 skill 描述为可复用的指令、参考资料和脚本，并采用渐进加载；因此本测试支持“skill 提高工作流一致性”，不支持“skill 改变底层模型能力”的结论。

更严格的下一轮实验应在同一模型、同一联网权限、同一参数下随机隐藏 A/B 标签，仅改变是否提供 skill；再由不知道答案来源的第二位评审者评分。
